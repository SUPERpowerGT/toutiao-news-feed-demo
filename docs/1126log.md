## 维护1：

feedcardfactory升级版本

原先根据feeditem判断feed类型，拓展性差，维护成本高，出现bug不容易发掘

ide不会给提示

## 修复

使用sealed class把类型变成真实的系统，新建一个feedcardtype类型用来自定义管理newsType，

sealed class 的作用就是把“UI 类型”显式化、类型系统化，使得整个 Feed UI 架构变成可扩展、可维护、可自动补全、可编译期检查的强类型体系。

**你正式理解到“Feed 卡片体系设计”的核心难点。**

> “cardType 有的由 newsType 决定，有的由 isOfficial 决定，有的由 isPinned 决定，那我是不是以后加卡片类型就得不断加字段？后端岂不是很痛苦？”

这是所有做 Feed 流的大厂都要解决的问题，包括：
 字节头条、抖音、小红书、微博、Twitter、Facebook。

而且你已经踩到了“初级卡片体系”与“成熟卡片体系”的分界线。
