# **02. 需求分析**

## **1. 项目背景**

本项目的目标是实现一个新闻类应用首页推荐流的示例系统。
 为了模拟真实新闻客户端的架构与交互方式，项目不仅包含 Android 客户端，还包括一个轻量级的 Go 后端，用于提供新闻内容的分页数据接口。

整个系统主要围绕“首页推荐列表”展开，不涉及复杂业务。项目重点放在：

- 列表内容展示
- 网络数据刷新与加载更多
- 数据缓存与弱网适配
- 基本后端数据服务
- 基于 MVVM 的应用架构

通过这个 Demo，开发者可以从零开始体验一个完整的移动应用开发流程。

------

## **2. 项目目标**

本项目希望通过一个可完整运行的示例，达到以下目标：

1. **实现新闻推荐流首页**：包括列表渲染、内容展示、刷新与分页。
2. **掌握 Jetpack Compose** 的基本用法与组件化 UI 思维。
3. **理解 MVVM 架构与 Repository 模式** 在客户端的应用方式。
4. **搭建一个简单可用的后端服务**：支持分页、排序与数据初始化。
5. **实现本地缓存与离线浏览**，提升应用在弱网场景下的可用性。
6. **形成完整的工程文档**：从需求、用例、架构、数据库设计到实现。

------

## **4. 功能需求**

### **4.1 基础功能**

这些功能构成推荐流页面的核心能力：

- **新闻列表展示**
   首页以列表形式呈现新闻内容，包括纯文字卡片、图文卡片等不同展示方式。
- **服务端数据加载**
   客户端需通过后端 API 获取内容列表，并在首页首次加载时展示。
- **下拉刷新**
   用户下拉后重新请求数据。刷新完成后页面应替换为最新内容。
- **分页加载**
   当用户滑动到底部时，自动请求下一页数据并追加展示。
- **本地缓存**
   成功加载的数据需写入本地 Room 数据库，便于下次打开时快速展示内容。

------

### **4.2 额外实现的功能**

为了使整体体验更完整，本项目会额外实现以下常见特性：

- **内容排序逻辑**：后端会为新闻设置权重字段，客户端可根据权重决定展示顺序。
- **骨架屏（占位 UI）**：在数据未加载完成前使用占位组件避免白屏。
- **简单动效**：新闻项加载与显示加入适当的淡入效果，使滚动体验更自然。
- **离线内容展示**：无网络时展示缓存数据，保证基本可用性。

------

### **4.3 架构相关需求**

为了保证可维护性和可扩展性，本项目在设计上提出以下要求：

- **卡片结构需要抽象化**
   使用 sealed class 来定义不同类型的新闻卡片，统一处理数据结构，便于未来扩展多图、多视频等类型。
- **卡片渲染逻辑模块化**
   使用工厂模式或策略模式，根据卡片类型决定具体的展示组件。
- **跳转逻辑预留**
   列表项点击后预留跳转入口，但本次不实现具体详情页。
- **频道栏（Tab）结构预留**
   App 顶部包含推荐/热点等频道的 UI，但不做频道切换逻辑，作为结构展示。

------

## **5. 非功能需求**

- **性能要求**
   列表滑动应保持流畅，分页加载需避免重复触发；刷新操作需在 1 秒内给用户反馈。
- **稳定性**
   网络异常时不应出现空白页面，应自动回退到本地缓存。
- **可维护性**
  - 客户端采用 MVVM 架构
  - 后端采用 Controller / Service / Repository 分层
  - 网络请求、缓存、UI 分离清晰
- **可扩展性**
   未来添加新的卡片类型、推荐规则或过滤逻辑时，应尽可能保持现有代码结构不变。
- **用户体验**
   在应用启动时优先加载本地缓存，在后台更新数据，使体验更自然。

------

## **6. 数据需求**

新闻数据结构至少包含以下内容：

- 标题
- 摘要
- 图片 URL（如无图片则为空）
- 发布时间
- 展示类型（文字、图文等）
- 展示权重（用于简单的排序）

后端数据库需要负责：

- 数据持久化
- 分页读取
- 批量导入初始内容（seed 脚本支持）

客户端负责：

- 本地缓存
- 缓存更新
- 离线读取

------

## **7. 不纳入本次开发范围**

本项目保持范围适中，以下功能不在本次开发计划内：

- 视频播放与短视频流
- 搜索功能（仅提供界面）
- 新闻详情页
- 用户登录、收藏、点赞等交互
- 后台管理系统
- 复杂推荐算法（本项目使用简化权重）
- 多端适配（仅实现 Android）
