# **09. 核心功能说明（Core Function Description）**

本章节从业务流程角度描述本项目的核心功能，包括推荐流加载、分页策略、新闻详情加载、缓存策略以及 UI 展示逻辑。
 核心目标是实现一个高体验度的内容推荐首页，包括：

- 秒开体验
- 多卡片渲染
- 下拉刷新
- 向下滚动分页
- 本地缓存
- 弱网兜底

------

# **9.1 推荐流首页（Feed List）**

推荐流首页是本项目的核心功能，负责向用户展示“内容流”。
 其核心需求包括：

### **（1）多卡片渲染**

根据 `display_type` 字段渲染不同的 UI 卡片：

- 纯文字卡片（text）
- 大图卡片（image）
- 三图卡片（multi_image）
- 视频卡片（video）
- 横滑视频 / 多媒体卡片（multi_video）

> 通过 sealed class + Compose 实现“卡片工厂”，便于后续扩展。

### **（2）首页数据加载流程**

首次进入首页，流程如下：

```
App 启动 → 读取 Room 缓存 → 展示缓存内容（0.1s 内）
          ↓
后台协程发起网络请求 → /api/feed
          ↓
新数据覆盖缓存 → UI 自动刷新列表
```

通过“缓存优先 + 异步更新”策略实现首页秒开。

### **（3）滚动分页加载**

用户下滑到底部时触发分页加载：

- ViewModel 提取上一页的 `nextCursor`
- 调用 `/api/feed?cursor=xxx&limit=10`
- 服务端返回下一页数据与新的 `nextCursor`
- 前端合并列表并避免重复

分页特点：

- 无重复内容
- 数据连续性强
- 新内容插入不会影响用户已浏览部分

### **（4）下拉刷新**

下拉刷新执行以下步骤：

1. 清空页面状态
2. 重新请求 `/api/feed`（不带 cursor）
3. 覆盖 Room 缓存
4. UI 刷新展示最新内容

刷新的内容一定更新，因为 cursor 机制使“新数据一定排序在最前面”。

------

# **9.2 新闻详情页（News Detail）**

点击首页任意卡片进入新闻详情页。

主要内容包括：

- 标题
- 作者信息
- 发布时间
- 富文本正文（HTML）
- JSON 结构化内容（供客户端渲染）
- 媒体内容（图片 / 视频）
- 互动统计（点赞、评论数等）

### **详情页加载流程**

```
点击卡片 → 跳转详情页 → 显示骨架屏
           ↓
请求 `/api/news/{id}`
           ↓
解析 HTML 或 JSON → Compose 渲染正文
```

采用双格式原因：

- `content_html`：用于通用渲染
- `content_json`：用于更准确控制图文混排（例如插入图片块）

------

# **9.3 内容媒体加载（Image / Video）**

媒体资源来自 `media` 表，通过 FeedItem 中预聚合后的字段传递到前端。

### 图片加载（Image）

- 客户端使用 Coil 加载图片
- 使用 LazyList + AsyncImage 实现高性能加载
- 支持自动占位图与渐进式渲染

### 视频封面（Video Cover）

- 来自 `media.cover_url` 字段
- 后端可来自手动上传或自动截帧（Demo 中使用静态封面即可）

------

# **9.4 本地缓存与离线体验（Room）**

首页使用 Room 缓存：

- 最近 30～50 条 feed 数据
- 最近查询的 media、news 部分字段
- 显示历史内容，即使无网络也能浏览

缓存策略：

### 初次加载

优先展示 Room 内容，提高启动速度。

### 网络覆盖（覆盖式缓存）

当接口返回新数据时：

- 清空旧缓存
- 写入最新 feed 列表

### 分页附加（追加式缓存）

分页数据 append 到 Room，避免重复数据。

------

# **9.5 并发与状态管理（ViewModel + Flow）**

首页涉及多个并发事件：

- 首屏加载
- 分页加载
- 下拉刷新
- 后台更新缓存

为避免冲突，ViewModel 内部维护三个互斥状态：

- `isLoading`
- `isRefreshing`
- `isLoadingMore`

状态机确保以下行为：

- 刷新时不允许分页
- 分页时不允许再次分页
- 首屏加载与刷新互斥
- 状态变化仅由 ViewModel 控制（UI 不直接修改数据）

------

# **9.6 弱网与错误处理机制**

### 错误类型：

- 网络不可用
- 超时
- 500 服务端错误
- 数据解析错误

### 客户端处理：

- 展示错误提示条
- 骨架屏与重试按钮
- 分页失败时不清空已展示内容
- 无网络 → 使用缓存内容兜底

### 后端处理：

- 错误日志记录
- 可预期的错误返回结构：
   `{ code, message }`

# **9.7 用户体验优化策略**

### 骨架屏（Skeleton）

- 首页首次加载
- 分页加载

### 慢加载提示

- Refresh 指示器
- 底部 Loading 行为
- Media 占位图（浅灰、渐变）

### 滑动性能优化

- LazyColumn 渲染
- key() 保持卡片稳定 ID

# **9.8 小结**

推荐流 Demo 的核心功能包括：

- 多卡片信息流渲染
- Cursor 分页加载
- 下拉刷新
- 本地缓存（Room）
- 弱网兜底
- 图文/视频混排
- 清晰的 MVVM + Repository 架构

这些功能协同构成了一个完整的“今日头条首页”核心骨架，覆盖内容展示、数据加载、网络状态管理、缓存管理和用户体验优化等方面。
